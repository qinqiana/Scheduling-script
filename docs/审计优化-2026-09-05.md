## 已修复

| 优先级 | 问题及影响 | 改动 |
| --- | --- | --- |
| P1 | 批量 SQL 中途失败，前半部分仍留在内存，后续保存可能把失败操作写入磁盘 | runMany 使用事务，异常回滚；单条写入也走同一入口 |
| P1 | 直接覆盖唯一数据库，写入失败可能损坏文件；内存和磁盘可能不一致 | 临时文件写完后重命名替换；保存失败重新加载最后成功的磁盘版本 |

| P1 | Express 异步导出异常未接住，上传错误返回非 JSON | 导出捕获异常；恢复采用同步异常处理；增加统一 JSON 错误出口 |
| P1 | 开放 CORS，其他网站可读写本地服务 | 删除开放 CORS 中间件，拒绝非同源 Origin；保留 Vite 同源代理访问 |

| P2 | 生成和导入在批量写入内部重复导出整库 | 删除内部 persist，每批仅在事务成功后落盘一次 |
| P2 | SQL 绑定或执行出错可能不释放语句 | queryAll、execSql 使用 finally 释放 |
| P2 | 切换月份的旧加载响应覆盖新月份，统计页请求异常未处理 | 月历加载序号保护、切月清除旧数据和编辑格；统计页忽略过期响应并显示错误；操作中禁用年月切换 |

## 尚存限制

1. **黄金快照不是无冲突证明。** 2026-02、05、08、10 的合成输入分别保留 8、13、14、14 条硬冲突。初次基线运行耗时约 4、14、25、13 秒，均用尽 24 次尝试。尚未判定这些用例是否存在完全可行解，不能据此承诺生成结果满足所有硬约束。
2. **生成仍同步占用服务线程。** 本次消除了重复整库保存，但未改变生成阶段的计算耗时。后台执行需要同时处理引擎模块级状态与任务生命周期，未混入此次数据安全修复。
3. **存储仍是单进程整库保存。** 临时文件替换不等同于断电耐久性保证，不支持多个进程同时写同一 data.db。runMany 供同步、非嵌套的现有调用使用。
4. **备份验证不是全量业务数据修复。** SQLite 结构兼容性检查不能证明所有历史班次和规则组合都正确。原有官方假日覆盖及历史规则迁移语义未更改。
5. **keepLocked=false 仍未提供解锁重排语义。** 现有界面始终传 true，持久化仍优先保留锁定格；本次未改变锁定业务规则。

后续求解优化应先逐条归因现有硬冲突，区分输入不可行与修复算法未找到解，再用固定种子和可行性断言衡量改动，避免只让快照通过却掩盖排班问题。
